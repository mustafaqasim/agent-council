# Contributing

## Before changing behavior

1. Create a case for changes to safety boundaries, lifecycle rules, schemas, model routing, or release gates.
2. Keep public schema identifiers under the `agent-council.*` namespace.
3. Do not add customer-specific terminology, paths, records, credentials, or test evidence.
4. Add a focused contract test for each changed behavior.

## Verification

Run the commands in the Development section of the README. Changes to the plugin manifest, runtime, schemas, profiles, or skills require a fresh packaged-byte qualification and independent review before release.

## Claims

Do not claim model-provider execution, dynamic model discovery, broad platform support, or secret-free evidence unless the implementation and qualification evidence prove it.
